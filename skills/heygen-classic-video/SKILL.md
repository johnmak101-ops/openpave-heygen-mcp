## Tools (10)

| Tool | Live description (2026-11-12 snapshot) |
|---|---|
| `create_video_from_avatar` | Create a talking-avatar video from a confirmed avatar look ID and an exact script or audio source. Preserve the user's words and chosen avatar; never guess IDs or substitute a presenter silently. If no look is selected, use list_avatar_groups then list_avatar_looks and ask the user to choose. Audio and background media take a HeyGen asset ID or a public https URL, never a local or sandbox path (/mnt/data/..., file://); import or upload the file first and pass its asset ID. Poll get_video with the returned videoId until completed or failed; return video_url on completion. Use a server-provided retry delay, otherwise wait 30 seconds between polls. After five minutes, return the latest status and available video link so the user can resume later. Never resubmit creation to check progress. For open-ended creative production, use create_video_agent instead. |
| `create_video_from_cinematic_avatar` | Create a Cinematic Avatar video: a 4–15 second clip of one to three avatar looks driven by a natural-language prompt, plus optional reference images, videos or audio. Use it only when the user explicitly asks for Cinematic Avatar; a style word like "cinematic" is not such a request. There is no script or voice input, so exact wording is not guaranteed: describe the scene, the action and any words the person says in the prompt. A presenter speaking to camera uses create_video_from_avatar; other visual productions of 30 seconds or less use text_to_video. If it fails with plan_upgrade_required, explain that Cinematic Avatar is not included in the account's current plan, offer a talking-avatar video with create_video_from_avatar instead, and wait for the user's answer. Do not retry, switch tools on your own, or promote purchases or upgrades. If a public avatar is rejected, tell the user that Cinematic Avatar cannot use public studio avatars and let them choose one of their own avatars or an AI-generated public avatar; do not substitute one. Media inputs take a HeyGen asset_id or a public https URL, never a local or sandbox path (/mnt/data/..., file://); import or upload the file first and pass its asset_id. Poll get_video with the returned videoId until completed or failed; return video_url on completion. Use a server-provided retry delay, otherwise wait 30 seconds between polls. After five minutes, return the latest status and available video link so the user can resume later. Never resubmit creation to check progress. For open-ended creative production, use create_video_agent instead. |
| `create_video_from_image` | Create a talking video by animating one image of a person, with lip movements synced to a script spoken with voice_id or to supplied audio. Use an image of the user, of a person who agreed to have their likeness animated, or of a fictional person. The image must show one clearly visible, human-like face, such as a photo or a realistic illustration; for mascots, animals, objects or other non-human characters use image_to_video or reference_to_video instead. Returns video_id. Media inputs take a HeyGen asset_id or a public https URL, never a local or sandbox path (/mnt/data/..., file://); import or upload the file first and pass its asset_id. Poll get_video with the returned videoId until completed or failed; return video_url on completion. Use a server-provided retry delay, otherwise wait 30 seconds between polls. After five minutes, return the latest status and available video link so the user can resume later. Never resubmit creation to check progress. For open-ended creative production, use create_video_agent instead. |
| `create_video_from_studio` | Create a single video by composing an ordered list of whole-frame scenes. The server owns layout and center-crops each scene to the global output canvas. Output settings are global (one per request); a single video_id is returned and rendering is all-or-nothing. MP4 only in v1 — the output container is fixed and ``output_format`` is not exposed. Media inputs take a HeyGen asset_id or a public https URL, never a local or sandbox path (/mnt/data/..., file://); import or upload the file first and pass its asset_id. Poll get_video with the returned videoId until completed or failed; return video_url on completion. Use a server-provided retry delay, otherwise wait 30 seconds between polls. After five minutes, return the latest status and available video link so the user can resume later. Never resubmit creation to check progress. For open-ended creative production, use create_video_agent instead. |
| `get_video_voice_capabilities` | Lists the voice engines and models offered for each language and accent when creating a video. Availability of a specific voice also depends on its ownership and setup. |
| `get_video` | Get a HeyGen video's status and playback URL. Use for IDs from create_video_from_avatar, create_video_from_image, create_video_from_studio, create_video_from_cinematic_avatar, generate_from_template, or completed Video Agent sessions. For text_to_video, image_to_video, and reference_to_video IDs, use get_model_video instead. Return video_url when completed. On failed, explain failure_message and stop; do not regenerate or report a historical failure automatically. For pending or processing, honor a returned retry delay or wait 30 seconds. After five minutes, share the status and video_page_url for later follow-up. |
| `list_videos` | List videos in the account, optionally filtered by folder ID or title substring. Use this for 'show me all my HeyGen videos', 'show my videos', 'list my videos', and other library-browsing requests. Present the gallery or list; do not replace it with the most recent video or automatically play a result. Omit limit for the initial browse (default 10); asking for all videos does not mean fetching 100 at once. Gallery pages are capped at 24 and load more as the user scrolls; do not eagerly fetch every page. Describe the returned page, not the entire library. Widget-capable hosts display a scrollable thumbnail gallery with search and pagination. Other clients receive the paginated video JSON. This lists videos, not editable drafts or folders. Before opening a selected video, use get_video and only call show_video if status is not failed. For an explicit request like 'show my latest video', call lookup_videos instead to look up IDs without opening a gallery, select the newest completed item, verify it with get_video, and call show_video once. Explain if a newer failed attempt was skipped; if none are playable, report that without opening failed players. |
| `lookup_videos` | List video IDs and metadata as paginated JSON without opening a widget. Use this for selecting a video for a follow-up tool, including 'show my latest video'. Choose the newest completed item and verify it with get_video before presenting it. Explain if a newer failed attempt was skipped; if none are playable, report that without opening failed players. For browsing the library, use list_videos instead. |
| `get_video_scenes` | Returns a video's scenes as it stands now, with the `edit_version` to send when editing. Each scene has a `background`, placed `elements` and a `script`. Skip element types you do not recognize. Geometry, text content, animations and background music are not described. A video whose editor document is still being prepared returns `409 resource_not_ready`; retry after it advances. |
| `delete_video` | Permanently deletes a video and its associated files. This action cannot be undone. |
